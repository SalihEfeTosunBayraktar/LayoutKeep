1. The two things called "Laya"

The repository you sent is not a chat assistant. It is a non-autoregressive decision engine: you give it a state (text, email, ticket, JSON) and typed questions, and it answers in a single forward pass with a calibrated probability. It never generates text, so there is nothing to parse and nothing to hallucinate. Three question primitives: choice (pick one of these), score (where on this ordered scale), noul (probability that this is true).

Three checkpoints ship with it: laya (ModernBERT-large, 421M, 512 tokens, English), laya-multilingual (mmBERT-base, 322M, 1024 tokens, 100+ languages) and laya-typed-decisions; a Router detects the script and language in under 0.5 ms and picks the right one. Apache-2.0, pip install laya. The technique descends from the author's own March 2025 paper (arXiv:2503.23303) and RLCD training — reinforcement learning against strictly proper scoring rules, which is what makes the confidence numbers mean something.

Sources: repo README, Hugging Face model card, PyPI page.

2. The alternative you named: Jev, by TypeSafe

Jev is the same idea as a hosted frontier model — announced 2026-09-14, weights not published, early access via a waitlist, and reachable through OpenRouter's decisions endpoint. It is the accuracy ceiling in every independent comparison, and it is closed, hosted, and priced per token. For a local-first project that is a data-egress decision, not just a cost one.

Where Laya is strong, where it is weak

Strong

  • Speed: 30 ms/case measured; the fastest thing in the comparison by 1.5×.
  • Router: 45 of 51 languages usable, versus 23 for the English-only checkpoint — and it detects non-Latin script in <0.5 ms, before any forward pass.
  • Fine-tuning is the product: base checkpoints are near chance zero-shot on typed decisions (0.36 / 0.35 against a 0.318 random baseline); the fine-tuned checkpoint reaches 0.766, above Jev's published 0.727.
  • Fine-tune cost: ~4–5 h on 2×T4 (a free Kaggle session) for 4 epochs over ~30k questions.

Weak — read this before planning

  • Yes/no (noul) is the weak primitive: 0.5–0.7 on the independent suite, "coin-flip territory" on questions like does this contain a credential.
  • Ordinal score is weakest of all (SST-5 0.372 in the vendor's own numbers).
  • The English checkpoint collapses on non-Latin scripts — Khmer scored 0.000 accuracy at 0.952 confidence, so confidence gating cannot save you. Route, or pick deliberately.
  • 512 tokens per question, English on the base checkpoint; calibration is measured on their data, not ours.

5. What it costs us, honestly

  • VRAM is the real bill. The standing rule here is one model in the LM Studio server at a time; Laya is a second process, and on this 8 GB laptop GPU it competes with the translator. CPU is the honest default for it (193–464 ms preloaded, 7–10 s per switch if not).
  • Preload, or don't bother. Without Router(preload=True) every language switch reloads a checkpoint; that is the 7–10 s figure, not 33 ms.
  • Zero-shot is not enough for the domain decisions. Language detection is a general capability and can be used as-is. Document-type routing and flag triage need a fine-tune on our own runs — which is the work, not the model.
  • The repository is two days old. The method is a year old and published; the packaging is not. Pin a version, keep it optional, and never let it become load-bearing before it has passed a measured test on our own documents.

6. The plan I would actually run

  1. Spike 1 — language detection (a day). Run laya-multilingual over the first page of every held-out document and compare its answer with the language we know is right. Acceptance: it agrees on all of them, and reports the script for the non-Latin ones (the pipeline's known weak spot). No fine-tune, no integration — a script and a table.
  2. Spike 2 — flag triage (a day). Run GLiNER2 and Bonsai-1bit over the flagged blocks of two recorded runs, with our own labels from the audits. Acceptance: better than the heuristic on the same blocks, at a cost we can afford per run.
  3. Only then decide. If spike 1 lands, it goes behind a setting (detect.language_model = heuristic | laya) with the heuristic as the default. If spike 2 lands, the same shape. Nothing ships that we have not measured on our own pages.
